# Reproduction notes

## Included and missing artifacts

Included: three supplied notebooks with their saved outputs, project-oriented copies without outputs, the split JSON, extracted plots, and the report body. Missing: ECG CSVs, `.keras` trained weights, exact original environment lock, stable accepted-record manifest, and training logs beyond saved notebook outputs.

## Run order

1. Install `requirements.txt` into a fresh Python 3.11 environment.
2. Download and extract the dataset; see `data/README.md`. Launch Jupyter from the repository root or `notebooks/`.
3. Run notebook 01. It writes `artifacts/best_overall_lstm_model.keras`.
4. Run notebook 02. It writes `artifacts/best_overall_gru_model.keras`.
5. Run notebook 03 with both weights present.

Dependencies are bounded compatibility suggestions inferred from imports, not a tested GPU-training lock. TensorFlow/accelerator installation depends on the host. The full 650,000×92 array and derived windows require substantial RAM. Random seeds do not guarantee bitwise-identical accelerator results.

## Assumptions to revisit

- One augmentation per accepted MLII record, interleaved column order, 46 records, and 650,000 samples per record. Some label-building code hardcodes 92 columns.
- Split indices separate record groups under that layout; they do not establish unique patient identities.
- Peak labels are generated by NeuroKit2. A detection failure becomes an empty peak list, which can mislabel affected windows as negative.
- No expert-annotated external test set, real-noise benchmark, uncertainty intervals, or repeated-seed evaluation is supplied.

Validation performed during packaging is recorded in `VERIFICATION.md`; it does not establish training reproducibility.
